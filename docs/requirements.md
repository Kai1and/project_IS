# Требования к обработке заказа

Область: АИС «Доставка еды», оплата при получении, доставку организует ресторан. Отдельное приложение курьера и эквайринг в первый выпуск не входят.

## R-ORD-01 Последовательность состояний

Основной маршрут: «Создан» → «Принят» → «Готовится» → «Готов» → «Передан курьеру» → «Доставлен». До передачи курьеру оператор может отменить заказ с указанием причины. После передачи отмену рассматривает поддержка; эта операция не входит в учебную функцию оператора. Состояния «Доставлен» и «Отменён» конечные.

Критерий проверки: переход «Готовится» → «Доставлен» отклоняется, прямой переход из конечного состояния запрещён.

## R-ORD-02 Версия и принадлежность заказа

Оператор меняет только заказ своего ресторана. Команда содержит ожидаемую версию; сопоставление версии и запись нового состояния выполняются атомарно. При конфликте версия не увеличивается, пользователь перечитывает актуальный заказ. Для отмены обязательна причина.

Критерий проверки: из двух команд «Принять» и «Отменить», пришедших с одной версией, проходит ровно одна. Версия заказа увеличивается ровно на единицу; проигравшая команда получает конфликт, чужой ресторан — отказ в доступе.
